# LUXE PARTY TOKYO サイト

スプレッドシートで内容を書き、Driveに画像を置き、ボタンを押すと GitHub Pages が更新される仕組みです。
ビルドツールもサーバーも不要で、費用はかかりません。

---

## 1. 全体の流れ

```
Googleスプレッドシート（文章・日付・価格）
Googleドライブ（イベントごとのフォルダに画像）
        ↓  メニュー「サイト → サイトを更新」
Google Apps Script が HTML を組み立て、GitHub に 1コミットで反映
        ↓  1〜2分
GitHub Pages に公開
```

- 開催予定のイベントが **トップページ** になります
- 終演時刻を過ぎたイベントは **自動でアーカイブ** に移動します（手作業なし）
- 全イベントは `events/{id}/` に個別ページとして残り続けます

---

## 2. 初回セットアップ

### 2-1. リポジトリ
1. GitHub に新しいリポジトリを作る（private でも可）
2. このフォルダ一式をアップロード
3. Settings → Pages → Source を `main` ブランチのルートに設定

### 2-2. Drive
1. 親フォルダを1つ作る（例：`LUXE_SITE`）
2. その中に **イベントIDと同じ名前のフォルダ** を作る（例：`2026-09-12-vol24`）
3. 画像をそこに入れる。共有設定は変更不要（公開しません）

### 2-3. スプレッドシート
1. 新しいスプレッドシートを作る
2. 拡張機能 → Apps Script を開き、`gas/Code.gs` と `_shared/render.js` の中身を
   それぞれ `Code.gs` `render.gs` として貼り付ける
3. 保存してスプレッドシートを開き直すと、メニューに **「サイト」** が出ます
4. 「サイト → シートのひな形を作る」を実行
5. `config` タブを埋める

### 2-4. GitHubトークン
1. GitHub → Settings → Developer settings → **Fine-grained personal access token**
2. 対象リポジトリのみ選択、権限は **Contents: Read and write** だけ
3. Apps Script の 設定 → スクリプトプロパティに
   `GITHUB_TOKEN` = 発行したトークン を登録
4. 「サイト → 設定を確認する」で疎通確認

> トークンには有効期限があります。切れると更新が止まるので、
> 期限日をカレンダーに入れておいてください。

## 3. シートの書き方

### `events` タブ（1行 = 1イベント）

| 列 | 例 | 説明 |
|---|---|---|
| id | `2026-09-12-vol24` | 半角英数字とハイフンのみ。Driveのフォルダ名と一致させる |
| title | `MIDNIGHT\|VELVET` | `\|` で改行。2行目が金色になります |
| edition | `LUXE PARTY TOKYO VOL.24` | ヒーロー上部の小さい行 |
| date | `2026-09-12` | この形式のみ |
| day | `SAT` | 曜日表記 |
| open / close | `22:00` / `05:00` | close が open より小さいと翌朝扱い |
| venue | `1OAK` | |
| heroImage | `hero.jpg\|フロアの写真` | `\|` の後は代替テキスト（読み上げ・画像が出ない時用） |
| ogpImage | `hero.jpg` | 空ならheroImageを使用 |
| lead | 一文の説明 | 検索結果とSNSシェアに出ます |
| entryUrl | 登録システムのURL | 空ならエントリーボタンは出ません |
| published | ✓ | 外すとサイトに出ません |

### `blocks` タブ（1行 = ページ上の1ブロック）

`order` の順に上から並びます。行を入れ替えれば配置が変わります。

| type | 使う列 | 書き方 |
|---|---|---|
| `text` | title, body | bodyの改行が段落になります |
| `image` | image, body | bodyはキャプション |
| `gallery` | image | `g1.jpg\|説明, g2.jpg, g3.jpg` とカンマ区切り |
| `lineup` | body | `DJ AAA / HEADLINE / https://instagram.com/aaa` を1行ずつ |
| `table` | body | `VVIP \| 12名まで \| ¥300,000 \| 備考` を1行ずつ。上の行ほど金の縁が強くなります |
| `news` | body | `2026.08.01 \| TICKET \| 本文` を1行ずつ |
| `entry` | body, link | linkに登録URL。ボタンになります |
| `access` | body, link | linkに住所か地図URL。地図が埋め込まれます |
| `embed` | link | YouTube か Instagramリール のURL |

`title` は **`ABOUT|夜だけの、もうひとつの東京`** のように書くと、
小さいラベル＋大見出し になります。`|` がなければラベルだけです。

知らない `type` を書いた行は無視されます（打ち間違いでページが壊れません）。

## 4. イベントごとの更新（毎回やること）

1. Drive に `新しいイベントID` のフォルダを作り、画像を入れる
2. `events` タブに1行足す
3. `blocks` タブに、そのイベントの行を足す（前回分をコピーして eventId を書き換えるのが早いです）
4. **サイト → サイトを更新**

所要10分程度。前回のイベントは何もしなくてもアーカイブに移ります。

公開前に確認したいときは **「プレビューを更新」** を使ってください。
`/preview/` に検索避け付きで出力され、本番は書き換わりません。

## 5. 画像について

- Drive に入れた画像は、Google側で **横幅1600pxに縮小されてから** 取り込まれます。
  事前の書き出しやリサイズは不要です（`config` の `imageMode` が `thumbnail` のとき）
- スマホ写真の向き（EXIF回転）も自動で補正されます
- ファイル名にはハッシュが付いて保存されるため、**差し替えても古い画像がキャッシュで残りません**
- 変更のない画像は再アップロードされないので、2回目以降の更新は速いです
- 縮小せず原本を使いたい場合は `imageMode` を `original` にしてください

### 動画
リポジトリには入れないでください（GitHub Pages は容量1GB・帯域100GB/月が目安です）。
YouTubeの限定公開かInstagramリールを `embed` ブロックで埋め込みます。

## 6. うまくいかないとき

| 症状 | 確認すること |
|---|---|
| 「公開を中止しました」と出る | 表示されたメッセージの通りにシートを直す。id の重複や日付形式が大半です |
| 画像が出ない | Driveのフォルダ名がイベントIDと一致しているか／ファイル名が完全一致しているか |
| 更新したのにサイトが変わらない | 反映に1〜2分。GitHubのCommits履歴に新しいコミットがあるか確認 |
| 突然すべて失敗する | GitHubトークンの有効期限切れが最有力。再発行してスクリプトプロパティを更新 |
| 何が起きたか分からない | `ログ` タブに毎回の結果が記録されます。失敗時はメールも届きます |

---

## 7. 非常口

- `data/site.json` に全データが入っているので、**スプレッドシートを失ってもサイトは復元できます**
- Apps Script が使えないときは、手元で `node tools/build-local.js` を実行しても同じサイトが生成できます
- 生成ロジックは `_shared/render.js` の1ファイルだけです（GAS側は同じ内容の `render.gs`）

---

## 8. デザインを変えたいとき

- 色・文字・余白 → `assets/site.css` の先頭 `:root` にまとまっています
- ページの骨格 → `_templates/event.html` / `_templates/archive.html`
- ブロックの見た目 → `_shared/render.js`（GASの `render.gs` にも同じ内容を反映してください）
